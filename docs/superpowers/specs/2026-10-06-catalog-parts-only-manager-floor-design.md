# 目录只按分块发布，旧管理器无法安装或更新

**日期：** 2026-10-06

现有目录 Mod 继续能手动放进游戏。通过管理器安装或更新时，需要 1.3.13 或更高版本。1.3.12 及更早会在下载这一步失败。管理器的下载逻辑不改；1.3.13 在目录带有 `parts` 时已经只下载分块，不再请求整包地址。

改动在 MechabellumMods 仓库：`catalog.json`、分块文件、`scripts/validate_catalog.py`、`scripts/stamp_hashes.py`，以及 GitHub Release 整包附件和镜像上的整包对象。管理器下载逻辑不改。本仓库的 `MirrorCatalogPublisher` 要改，避免以后的发布把整包写回旧路径。已经发出去的 1.3.13 直传改不了，见下文。

## 已确认的行为

- 新安装和更新走同一条下载。两边都要失败。
- 本地库里的副本和目录 `sha256` 已经一致时，管理器不会重新下载。这个判断 1.3.13 和更早版本相同。不改哈希去逼它重下，否则 1.3.13 也会把没变的 DLL 再下一遍。
- 失败弹窗沿用旧管理器已有的句子：`加入本地库失败：All remote fetch candidates failed: … HTTP 404`。1.3.12 的程序改不了，弹窗里写不进新句子。
- 「从管理器安装或更新需要 1.3.13 或更高版本」写在简介最前面。界面按语言选用简介，所以默认简介和每一条非空的 `locales` 简介都要加上。
- 手动放入游戏目录的 DLL 不经过这条下载，字节也不改。

## 目录条目

保留 `id`、`name`、`file`、`sha256`、`size`、版本、预览、分类、标签、互斥。`file` 仍是拼好之后的 DLL 文件名，管理器用它给入库文件命名。`sha256` 和 `size` 仍是拼好之后那一个文件的校验。

小于 100MB 的条目增加一块：

```json
"parts": [
  {
    "file": "mods/<id>/parts/0000",
    "sha256": "<与条目 sha256 相同>",
    "size": "<与条目 size 相同>"
  }
]
```

分块路径不得等于 `file`。相等时，1.3.12 会按 `file` 把这一块当成整包下下来，哈希对得上，安装就会成功。

`cut-guide` 已有 `mods/cut-guide/parts/0000` 到 `0004`。块路径和块内容不动，只去掉它的 `originUrl`。

每条都删除 `originUrl`。

简介前缀接在现有文字前面，后面空一格，不改后文：

| 位置 | 前缀 |
| --- | --- |
| 默认 `summary`（简体中文） | 从管理器安装或更新需要 1.3.13 或更高版本。 |
| `locales.en.summary` | Installing or updating through the manager requires 1.3.13 or newer. |
| `locales.de.summary` | Installation oder Aktualisierung über den Manager erfordert 1.3.13 oder neuer. |
| `locales.ja.summary` | マネージャーからのインストールと更新には 1.3.13 以降が必要です。 |
| `locales.ru.summary` | Установка и обновление через менеджер требуют версию 1.3.13 или новее. |

某一语言没有 `summary` 时不用补空对象，界面会退回默认简介。目录根上的 `updatedAt` 前进。

## 发布顺序

分两段做。第一段结束时，旧管理器仍然能装。门闩在第二段删除整包之后才关上。

**第一段。** 先把分块字节放到 Git 仓库和镜像的分块路径上。然后才推送 `catalog.json`：带上 `parts`，去掉 `originUrl`，写上简介前缀。整包 DLL 先留着，三处都留：

- 仓库里的 `file` 路径
- GitHub Release 上的整包附件
- 镜像键 `MechabellumMods/<file>`

1.3.13 把目录缓存在磁盘上，12 小时内启动不再请求网络。缓存在第一段之前写成的客户端，内存和磁盘里仍是旧条目：没有 `parts`，下载仍走整包地址。第一段立刻删掉整包的话，这些 1.3.13 会在静默期里安装失败，直到缓存过期或玩家手动刷新目录。手动刷新使用 `forceCold`，不受这 12 小时限制。

1.3.12 没有这 12 小时的磁盘静默，下次启动就会拿到新目录。新目录没有 `originUrl` 时，它仍会请求仓库里的 `file` 和镜像上的同名对象。整包还在，所以它仍然能装上。

**第二段。** 先用不带缓存的 GET 确认 GitHub raw 和镜像上的 `catalog.json` 都已经是新目录：每条都有 `parts`，都没有 `originUrl`。从这一刻起再等 **24 小时**，然后删除上面三处整包。

等 24 小时，是因为磁盘静默是 12 小时。新目录公开后的头 12 小时里，若有客户端仍拿到旧目录并写进自己的缓存，他的静默期会再延续 12 小时。只等 12 小时就删除，这段缓存会撞上删除，1.3.13 的安装和更新会 404。24 小时覆盖这一整段。

删除前再确认两条目录仍是新目录。整包此时还应在，所以删除前它们可以是 200。删除之后用一次不带缓存的 GET 确认三条整包地址都是 404。任一处仍返回 200，门闩还没关上，继续等。

第二段之后，一个连续开了超过 24 小时、且从未刷新目录的 1.3.13 进程仍握着旧目录，点安装会 404。按一次刷新目录，或关掉重开，就会改走分块。这是已发出程序的内存目录，本次改不掉。

## 校验脚本

`scripts/validate_catalog.py` 现在要求 `file` 指向的文件在仓库里，除非条目大于 100MB 且带有 https 的 `originUrl`。第二段删掉整包后，现有检查会报文件缺失。

第一段就改这条规则：

- 条目有非空 `parts` 时，各块都必须在仓库里，每块大于 0 且小于 100MB，块路径不得等于 `file`。拼起来的字节必须等于条目的 `sha256` 和 `size`。
- 此时 `file` 路径可以不存在。若 `file` 仍在仓库里，它的字节也必须等于同一套 `sha256` 和 `size`。第一段整包还在，两套都必须对上，避免分块和整包不是同一个 DLL。
- 没有 `parts` 的条目维持原规则。

`scripts/stamp_hashes.py` 对带 `parts` 的条目：

- 整包还在时，用整包字节填写 `sha256` 和 `size`，并要求与分块拼起来的结果相同，不同则失败退出。
- 整包已经不在时，用分块拼起来的字节填写 `sha256` 和 `size`，不得再报「file not found」。
- 无论是否传入 `--origin-base`，都不写回 `originUrl`。没有 `parts` 的条目保持现在的行为。

## 以后的直传

`MirrorCatalogPublisher.Plan` 现在把 DLL 传到 `MechabellumMods/<file>`。这正是 1.3.12 会去下的整包键。直传上限是 95MB，一块放得下。

本仓库改为：

- `file` 仍是拼好后的 DLL 相对路径，`sha256` 和 `size` 仍是这份 DLL。
- 上传只放到 `MechabellumMods/mods/<id>/parts/0000`。计划里的上传列表不得出现 `MechabellumMods/<file>`。
- 条目写入单块 `parts`（路径 `mods/<id>/parts/0000`，哈希和大小与整包相同），并去掉 `originUrl`。`Plan` 写出的 `CatalogJson` 和 `EntryJson` 都要这样。
- `MergeListedEntry` 把条目里的 `parts` 抄进目录，并删掉该条目的 `originUrl`。只抄 `name` / `file` / `sha256` 而不抄 `parts` 的话，合并后的目录会丢掉分块；1.3.13 又会去下整包，第二段删除整包之后连新管理器也装不上。
- 预览仍上传到 `MechabellumMods/mods/<id>/preview.png`。

已经发出去的 1.3.13 仍会把 DLL 传到旧键。这个二进制改不了。第二段之后不要用 1.3.13 的直传覆盖这些 Mod。镜像同步若只追加、不删除，第二段必须单独删除旧键。

## 核对

对照已发布的 1.3.12 与 1.3.13 下载代码，下面这些如果漏做，方案会在功能上失败：

- 只加 `parts`、不删整包：1.3.12 忽略 `parts`，仍从 `file`、`originUrl` 或镜像整包装上。
- 分块路径等于 `file`：1.3.12 下载到的就是 DLL，哈希通过。
- 第一段立刻删除整包，或只等 12 小时：旧目录缓存会撞上删除，1.3.13 的安装和更新一起失败。要等 24 小时。
- 只删 GitHub Release 附件：1.3.12 在配置了镜像且文件大于 100MB 时只请求镜像整包，不请求 `originUrl`。`cut-guide` 属于这一类。小于 100MB 的条目会再试仓库路径和镜像路径。三处都要删。
- 只改默认简介：en、de、ja、ru 有自己的 `summary` 时，界面用该语言的简介，看不到中文前缀。
- 改掉条目 `sha256` 来迫使「已是最新」再下载：1.3.13 会把未变化的 DLL 再装一遍。
