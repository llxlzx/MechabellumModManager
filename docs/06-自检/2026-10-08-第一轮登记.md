### 失败 1：界面文案与测试不一致

- 现象：`UiLanguageSwitchTests.Switching_language_refreshes_dirty_and_status_labels` 要求 `vm.Ui.GuideNav` 为「新手教程」（长度 4），实际是「管理器教程」（长度 5）。失败在断言第 93 行，英文半段还没跑到。
- 路径：`tests/MechabellumModManager.Tests/UiLanguageSwitchTests.cs`；现行文案在 `src/MechabellumModManager/Resources/Strings.resx` 的 `GuideNav` / `GuideTitle`。英文资源已是 “Manager guide”。
- 严重度：阻断（整套 `dotnet test` 因此不绿）。产品字符串与资源文件一致，像是文案改了、测试没跟着改。
- 下一轮：单独改测试期望，或改回文案。不要并进 C1。

### 失败 2：间隔清零后不再拉取目录

- 现象：`ModUpdateFlowTests.A_second_switch_inside_the_throttle_window_does_not_refetch`。热窗口内第二次切回库没有失败在「不得重复请求」那一行；失败在把 `SilentCatalogRefreshInterval` 设为 `TimeSpan.Zero` 之后的第三次切换。5 秒内 `handler.Requests.Count` 仍为 1，期望大于 1（“an expired window has to refetch”）。
- 路径：`tests/MechabellumModManager.Tests/ModUpdateFlowTests.cs` 约第 338–347 行；行为在 `MainViewModel` 的静默目录刷新。
- 严重度：风险。默认 15 分钟热窗口的「新鲜目录不重复拉」这一段没有在这次失败里被否定。被否定的是间隔为 0 时必须再请求。玩家若把静默刷新间隔收成 0，切回库可能仍不重新拉目录。
- 下一轮：单独修这个刷新路径并保留该测试。不要并进 C1 的门禁合并。

### 不稳定：界面缩放

- 现象：归档前那次全量没有这两条。归档后的 Debug 全量失败了 `UiScaleHostTests.Height_sized_dialog_grows_so_scaled_buttons_stay_fully_visible` 和 `Mail_provider_dialog_follows_scale_without_compounding_or_clipping_buttons`。紧接着单独跑 `UiScaleHostTests`，3 个测试都过（163 ms）。安静日志没有打印断言原文。
- 路径：`tests/MechabellumModManager.Tests/UiScaleHostTests.cs`。两个用例都把 `UiScaleHost` 设成 1.5，再量窗口和按钮。
- 严重度：风险。源码这期间没有改，更像是全量运行时静态缩放或 STA 泵互相影响，而不是归档弄坏了界面。
- 下一轮：单独把缩放测试收成不依赖其它用例的状态。不要并进 C1。

### 不稳定：清理脚本在可执行文件缺失时退出

- 现象：Release 全量里 `SanitizeAcfSnapshotsCliTests.Timed_cli_wrapper_exits_when_exe_missing` 失败一次。随后单独重跑这条和邮件缩放那条，两条都过。下一次 Debug 全量不再出现这条。没有留下断言原文。用例本身要求：脚本在，指向一个不存在的 exe，15 秒内进程结束且退出码不是 0。
- 路径：`tests/MechabellumModManager.Tests/SanitizeAcfSnapshotsCliTests.cs`；脚本 `packaging/installer/scripts/Run-SanitizeAcfCli.ps1`。
- 严重度：风险。
- 下一轮：若再出现，先看是挂起还是退出码 0，再改脚本或加长等待。不要并进 C1。

## 逻辑

C1 Phase 0 的 `SteamLifecycle` 已在 `src/MechabellumModManager/Services/SteamLifecycle.cs`。Phase 1 的 `ManagerSessionFacts` / `ManagerSessionPolicy` 在 `src/` 中不存在。

`MainViewModel.IsSessionLocked` 仍是五件事的或：恢复门、等待 Steam 结算、切服向导、切服忙、任务条会话锁。`IsCriticalOpRunning` 另算，不在这个属性里。这就是 C1 说的多套门禁并列。严重度：风险。下一轮：C1 Phase 1，先合成一个快照，再谈拆文件。

组装有两条路。`App.ComposeMainViewModel` 传入库、部署、切服、探针和一批对话框委托，不传 `ModCatalogService` 和 `UpdateChecker`。`MainViewModel` 构造函数对缺省参数执行 `new ModCatalogService()`、`new UpdateChecker()`、`new SteamLifecycle(...)` 等。正式窗口走内部 new；测试可以传入替身。严重度：风险。下一轮：C1 Phase 3 之后的宿主端口再收成一条组装路径。本轮不改。

体积（总行数，含空行）：`MainViewModel.cs` 6922，`BranchSwitchService.cs` 1885，`MainWindow.xaml` 2062，`ModCatalogService.cs` 非空行约 1095，`App.xaml.cs` 非空行约 460。相对 C1 规格撰写时的约 3800 / 1100 / 1250，ViewModel 和切服服务又长大了。严重度：风险。顺序仍是 Phase 1 → 2 → 3，不因为文件大就先拆界面。
