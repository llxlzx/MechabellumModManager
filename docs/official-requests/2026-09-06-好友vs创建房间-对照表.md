# 好友列表 vs 创建房间 — 一页对照

| | **好友列表** | **创建房间（官服）** | **创建房间 · 沙盒空架子（需官方）** |
|--|--------------|---------------------|-------------------------------------|
| **目标** | 关注通讯录更好用 | 开房体验/协议内补齐 | 补给、禁单位/科技等自由规则 |
| **不靠官方就能做** | 搜索/筛选/排序/拉全列表；状态分组着色；行内接已有 API：观战/加入/私聊/取关/拉黑；可选 Discord 快捷 | 按模式尊重 UI：预设、校验、失败重试；异变窗搜索/分类；仅补「本模式协议已有、UI 未露」的旋钮 | —（没有官方架子则不能合规联网自由改规则） |
| **做不到（不靠官方）** | 自建好友图、云备注/分组、站内完整私信、对局内比分/回合详情、强行互关 | 下拉没有的新模式；试验场级改补给/禁科技并当正式规则；修服务器故障；跨模式把所有旋钮塞一张表 | 私自改战斗且过排位战报校验（易 Data Error） |
| **要不要求官方** | **一般不需要**（调已有 `FriendProxy` 即可） | **协议内 QoL：不需要**；自由自定义：**需要** | **需要（最省事三件）**：① 沙盒不计分 ② 规则包只同步不解释 ③ 沙盒放宽战报校验；内容/UI/Mod 社区自己做 |
| **官服战力/匹配分** | 基本不碰 | 普通房：不改结算逻辑则不碰 | 沙盒设计为**不计分**；普通房勿塞沙盒规则 |
| **法律/警告面** | 相对最低（纯 QoL） | 协议内 QoL 低；联网塞试验场工具 **高** | 有官方沙盒通道则可控；无官方却改战报则高 |
| **推荐优先级** | P1 可独立开干 | P1 先做协议内 QoL | P0 用频道申请推进；未批前不要做联网改规则 |

**一句话：** 好友列表 = 现在就能 Mod；创建房间好看/好用 = 现在就能 Mod；创建房间「真正自由规则」= 必须等官方沙盒空架子，否则不要硬做。
