# 国内镜像搭建 / Domestic mirror setup

面向维护者：给管理器和 Mod 目录搭一个国内可直连的镜像，让不翻墙的玩家也能刷新目录、下载 Mod、检查更新。

For maintainers: stand up a mainland-China mirror so players without a proxy can refresh the catalog, download mods, and check for updates.

## 0. 镜像解决什么、不解决什么

镜像只解决「下得快不快、连不连得上」。它**不**解决「玩家不知道要更新」——那是应用内 Mod 更新检测的职责（已在主线实现，随下一个版本发布，见「Mod 浏览」页的状态列与设置里的「启动时检查 Mod 更新」）。

两件事互相独立，但共用一个前提：`catalog.json` 每个条目都必须有 `sha256`。

---

## 1. 客户端契约（改镜像前必读）

管理器把三个路径写死在代码里，桶的目录结构必须逐字对应：

| 用途 | 客户端请求的 URL |
|------|------------------|
| 管理器更新清单 | `{镜像根}/MechabellumModManager/latest.json` |
| Mod 目录 | `{镜像根}/MechabellumMods/catalog.json` |
| Mod 文件与预览图 | `{镜像根}/MechabellumMods/{catalog.json 里的 file / preview 原样}` |

行为约定：

- **镜像优先，GitHub 兜底**。Mod 文件按 **镜像 → `catalog.json` 里的 `originUrl` → raw.githubusercontent.com** 依次尝试；任一环节失败（超时、404、5xx）自动走下一个，玩家无感。
- **必须 https**。填 `http://` 会被拒绝并写日志（`LogMirrorMustBeHttps`），等于没配镜像。
- **出厂默认国内 COS**。`MirrorBaseUrl` 为 `null`（从未配置）时管理器写入 `https://mmm-mirror-1312774738.cos.ap-shanghai.myqcloud.com`；玩家清空输入框后存为 `""`，只走 GitHub，且不再回填。
- **MelonLoader 的 zip 不走镜像**，那是硬编码的 GitHub 地址。
- **所有来源都强制校验 sha256**，包括 GitHub。没有任何域名豁免。
- **支持 gzip**。客户端开了自动解压，镜像可以给 `catalog.json` 带 `Content-Encoding: gzip`。
- **支持断点续传**。下载中断后重来会带 `Range` 接着上次的位置；桶不支持 Range 也只是退化成从头下，不会出错。

## 2. 两个必须先知道的坑

### 坑一：`catalog.json` 缺 `sha256` 会让镜像全线失败

从 v1.1.7 起，**经镜像下载的 Mod 如果目录里没有声明 `sha256`，客户端直接拒绝安装**。理由是：GitHub 走的是签名 TLS 的已知源，镜像不是，没有哈希就无从判断文件有没有被换掉。

所以顺序不能颠倒——先把哈希补齐，再上镜像。否则镜像一配上，所有 Mod 下载即刻全部报错，比不配镜像还糟。

```bash
cd <MechabellumMods 本地克隆>
python scripts/stamp_hashes.py      # 写入/刷新每个条目的 sha256
python scripts/validate_catalog.py  # CI 跑的同一套校验，哈希与磁盘文件必须一致
git add -A && git commit -m "..." && git push origin master
```

`tools/sync-mirror.ps1` 上传前会自己再查一遍，缺哈希会直接中止，不会传上去一个坏目录。

### 坑二：镜像域名里不能出现 `github`

`RemoteFetch.ClassifySource` 是按域名里**是否包含 `github` 字符串**来判定「这是不是 GitHub 源」的。如果你把镜像域名取成 `github-mirror.example.com`，客户端会把它当成可信的 GitHub 源，于是**跳过上面那条哈希强制要求**——镜像最需要的那层保护正好被绕过。

`tools/verify-mirror.ps1` 会检查这一点，`MirrorContractTests` 里也有一条测试钉住这个行为。

## 3. 选腾讯云 COS，不选阿里云 OSS

| | 腾讯云 COS（推荐） | 阿里云 OSS |
|---|---|---|
| 默认域名能否直接用 | 能。`{bucket}-{appid}.cos.{region}.myqcloud.com` 免备案可用 | **不能**。2025-03-20 后新开通的账号，中国内地 Bucket 用默认域名调数据类 API 直接返回 `PublicEndpointForbidden` |
| 要不要备案 | 用默认域名不需要 | 必须绑已备案的自有域名，备案需国内主体、耗时两三周 |
| 已知限制 | 2024 年后新建桶：浏览器不能在线预览（强制 `Content-Disposition: attachment`）、apk/ipa 不许下载 | — |

那条 attachment 限制对我们没影响：管理器用 `HttpClient` 直接读响应体，不经过浏览器；我们传的是 json / dll / png / exe，都不在禁止下载之列。

如果你以后要绑自有域名（更短、更好记、方便换供应商），备案完成后在 COS 控制台加「自定义源站域名」即可，客户端侧改一个设置项，零代码改动。

## 4. 成本估算

存储侧可以忽略：Mod 全量约 2.37 MB，`catalog.json` 约 11 KB，每月存储费不到一毛。

唯一的变量是 87 MB 的安装包。按外网流出 0.5 元/GB 估：

| 场景 | 月流量 | 月成本 |
|------|--------|--------|
| 只镜像元数据 + Mod（约 1000 玩家） | ~3 GB | **约 1.5 元** |
| 追加镜像安装包，500 次下载 | ~43 GB | 约 22 元 |
| 追加镜像安装包，1000 次下载 | ~85 GB | 约 44 元 |
| 追加镜像安装包，2000 次下载 | ~171 GB | 约 87 元 |

**建议先只镜像元数据和 Mod**，安装包继续走群文件 + GitHub，观察一个月真实用量再决定。

要镜像安装包，光把 exe 传上去没用。客户端检查更新时是把 `latest.json` 里的 `setupUrl` **原样交给浏览器打开**，自己并不下载，所以镜像那份 `latest.json` 的 `setupUrl` 必须指向镜像上的 exe，否则玩家仍然会被送去 GitHub，你付了存储和上传的钱却一次都不会被用到。

`sync-mirror.ps1` 默认不传安装包；加 `-IncludeSetup` 时必须同时给 `-MirrorBaseUrl`，脚本会在上传前把镜像那份 `latest.json` 的 `setupUrl` 改写成镜像地址（本地和 GitHub 上的那份不动，两个源各自指向自己的下载）。漏了 `-MirrorBaseUrl` 会直接报错中止，不会让你传一个没人用的安装包上去。

### 4.1 量级涨到几十 G / 几百 G 之后

上面的数字建立在「全量 2 MB」上。一旦 Mod 总量到几百 G，把全部内容都放进 COS 会让**存储费**（约 0.118 元/GB/月，500 G 约 59 元/月）和**流量费**（每一次下载都计费）同时失控。分层是唯一便宜的做法，而且不需要换云厂商：

| 层 | 放什么 | 谁付钱 | 作用 |
|----|--------|--------|------|
| GitHub Release | **全量** Mod 二进制，权威副本 | 免费、无限流量 | 兜底，任何 Mod 都下得到 |
| 腾讯云 COS | 热门子集（`tools/mirror-hot.txt` 里列的） | 你 | 国内加速，只为高频内容付费 |
| 仓库 git 树 | 只留元数据与预览图 | 免费 | 单文件超 100 MB GitHub 会拒推，大二进制不能进 git |

客户端按 **镜像 → `originUrl` → raw.githubusercontent.com** 的顺序逐个候选尝试，所以冷门 Mod 在 COS 上 404 是**预期行为**，会自动回落到 Release，玩家无感。`verify-mirror.ps1` 默认也据此只对热门子集强校验；要求全部命中时才加 `-RequireAll`。

配套的三件事：

- **`catalog.json` 里的 `originUrl`** 指向 Release 上的那份，由 `tools/publish-mods-release.ps1` 上传后自动回填。没有它，超过 100 MB 的 Mod 在 git 里根本不存在，raw 链接必然 404。
- **`size` 字段**是必填的。客户端用它做进度条总量和体积上下界校验；缺了会退化成「无限大」，等于没有护栏。
- **`catalog.json` 超过 1 MB 后自动 gzip 上传**（带 `Content-Encoding: gzip`）。JSON 压缩比约十倍，而这是桶里请求量最大的对象。客户端已开启自动解压，无需配合改动。

调整热门子集就是编辑 `tools/mirror-hot.txt`（一行一个 Mod id，`#` 开头是注释），下次 `sync-mirror.ps1` 生效。移出热门列表的 Mod 不会被自动删除，要省存储费需手动 `coscli rm`。

## 5. 建桶（需要在腾讯云控制台操作）

### 5.1 创建存储桶

1. 登录腾讯云 → 对象存储 COS → 存储桶列表 → **创建存储桶**
2. **名称**：起一个不含 `github` 的名字，例如 `mmm-mirror`。完整桶名会自动变成 `mmm-mirror-{你的APPID}`
3. **地域**：选离玩家近的，如 `ap-shanghai`（华东）或 `ap-guangzhou`（华南）
4. **访问权限**：**公有读私有写**。这一项必须选对——私有读会让所有玩家拿到 403
5. **存储类型**：**标准存储**（就是默认值，确认一眼别改）
6. 其余保持默认，创建

第 5 项容易被单价误导。低频存储表面便宜 0.02 元/GB/月，但有**最低 30 天存储**——每次发版覆盖 `latest.json`、`catalog.json` 都会被补收不足 30 天的差额——且读请求单价更高，而镜像的全部工作就是被反复读。归档类需要提前申请恢复才能读，玩家点下载会直接失败。智能分层还要额外收对象监控费。

这些都不值得权衡：全量内容才 2.37 MB，加上安装包也就 90 MB 上下，**存储费在哪种类型下都是几分钱**，真正的成本全在外网流出流量（见第 4 节）。

记下访问域名，形如：

```
https://mmm-mirror-1312774738.cos.ap-shanghai.myqcloud.com
```

这就是要填进管理器设置的**镜像根地址**（末尾不要斜杠）。

### 5.2 建一个只能写这一个桶的子用户

**绝对不要用主账号密钥跑上传脚本。** 主账号密钥泄露等于整个云账号失守。

1. 访问管理 CAM → 用户 → **新建用户** → 自定义创建
2. 访问方式只勾 **编程访问**，不要勾控制台登录
3. 不要在这一步套用任何预设策略，先创建
4. 记下子用户的 SecretId / SecretKey

#### 新建自定义策略（逐步）

预设策略里没有「只能写一个桶」这种粒度，必须自己建。路径容易找错，按下面走：

1. 打开 [CAM 策略页](https://console.cloud.tencent.com/cam/policy)（控制台左上角**云产品 → 访问管理 CAM → 策略**）
2. 点左上角蓝色 **新建自定义策略**
3. 弹窗里有两个入口，选 **按策略语法创建**（不要选「按策略生成器创建」，生成器点不出下面这套 action 组合）
4. 模板列表选 **空白模板**，点下一步
5. 策略名称填 `mmm-mirror-write`，把编辑框里的内容**全部删掉**，粘贴下面这段：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "cos:PutObject",
        "cos:PostObject",
        "cos:DeleteObject",
        "cos:GetObject",
        "cos:HeadObject",
        "cos:GetBucket",
        "cos:InitiateMultipartUpload",
        "cos:ListMultipartUploads",
        "cos:ListParts",
        "cos:UploadPart",
        "cos:CompleteMultipartUpload",
        "cos:AbortMultipartUpload"
      ],
      "resource": [
        "qcs::cos:ap-shanghai:uid/1312774738:mmm-mirror-1312774738/*"
      ]
    }
  ]
}
```

上面这段已经填好你的 APPID（`1312774738`）、地域（`ap-shanghai`）和桶名，可以直接用。三个位置的含义分别是：`uid/` 后面是 APPID，桶名必须带 APPID 后缀，结尾 `/*` 表示桶内所有对象。

6. 点 **完成**
7. 回到 [用户列表](https://console.cloud.tencent.com/cam/user)，点进刚建的子用户 → **权限** 标签 → **关联策略** → 从策略列表搜 `mmm-mirror-write` → 勾选 → 确定

几个容易踩的点：

- `resource` 结尾的 `/*` 只覆盖桶里的**对象**，不覆盖桶本身。`cos:GetBucket`（列举对象）作用在桶上，严格说需要再加一条不带 `/*` 的资源。coscli 的 `cp` 和 `head` 用不到列举，所以现在这样够用；如果以后想跑 `coscli ls`，在 `resource` 数组里补一行 `"qcs::cos:ap-shanghai:uid/1312774738:mmm-mirror-1312774738/"`。
- 分片上传那几个 action 是给 87 MB 安装包和后面的大 Mod 准备的。资源范围已经锁死在这一个桶，留着不增加风险。
- 这条策略**不需要**随新 Mod 增加而修改。`/*` 是通配的，以后新增多少 Mod、多少目录都自动覆盖。

### 5.3 配置费用与流量护栏

公有读的桶被人盯上刷流量是真实风险，装好水闸再上线：

1. COS 控制台 → 存储桶 → **安全管理 → 防盗链**：设置为白名单模式，或至少开启「空 Referer 拒绝」。注意管理器的 `HttpClient` 不发 Referer，所以**不能**开「空 Referer 拒绝」——用后面的流量告警替代
2. 云监控 → 告警配置 → **新建告警策略**，选 COS，指标「外网下行流量」，设一个日阈值（例如 5 GB），超了发短信/邮件
3. 费用中心 → **费用预警**：设一个月度金额阈值（例如 20 元）

阈值宁可设低——被通知一次太敏感，比被刷爆一个月才发现好得多。

## 6. 上传

装 [coscli](https://cloud.tencent.com/document/product/436/63143)，用 5.2 的子用户密钥初始化：

```powershell
coscli config init
# SecretId / SecretKey 填子用户的
# APPID、地域、桶名按 5.1 填
```

然后跑同步脚本：

```powershell
cd D:\gongzuo\钢铁指挥官mod管理器开发

# 先干跑一遍看要传什么，-WhatIf 只打印不上传
.\tools\sync-mirror.ps1 -Bucket mmm-mirror-1312774738 `
    -ModsRepo "D:\gongzuo\独立工作区\MechabellumMods" `
    -ReleaseDir .\release\v1.1.8 `
    -WhatIf

# 确认无误后真跑
.\tools\sync-mirror.ps1 -Bucket mmm-mirror-1312774738 `
    -ModsRepo "D:\gongzuo\独立工作区\MechabellumMods" `
    -ReleaseDir .\release\v1.1.8
```

要连安装包一起镜像，加这两个参数（必须成对出现）：

```powershell
.\tools\sync-mirror.ps1 -Bucket mmm-mirror-1312774738 `
    -ModsRepo "D:\gongzuo\独立工作区\MechabellumMods" `
    -ReleaseDir .\release\v1.1.8 `
    -IncludeSetup `
    -MirrorBaseUrl https://mmm-mirror-1312774738.cos.ap-shanghai.myqcloud.com
```

脚本做这几件值得注意的事：

- **上传前校验哈希**：`catalog.json` 里任何一条缺 `sha256` 就中止，绝不上传一个会让全站下载失败的目录
- **两个清单最后传**：先传 Mod 文件，最后才传 `catalog.json` 和 `latest.json`。顺序反了的话，同步过程中刷新的玩家会读到一份指向尚未上传文件的新目录
- **增量上传**：每个对象上传时把 sha256 写进自定义元数据，下次先 `HEAD` 比对，一致就跳过。几百 G 的库里改一个 Mod 只会重传那一个。要强制全量重传加 `-Force`
- **只传热门子集**：默认读 `tools/mirror-hot.txt`，只镜像列表里的 Mod（见 4.1）。用 `-HotList` 指向别的文件可临时换一套
- **`catalog.json` 超 1 MB 自动 gzip**：带 `Content-Encoding: gzip` 上传，对象名仍是 `catalog.json`
- **默认不传安装包**：要传加 `-IncludeSetup`，见第 4 节的成本权衡
- **传安装包时改写 `setupUrl`**：只改上传到镜像的那一份，本地文件不动；`-MirrorBaseUrl` 缺失、不是 https、或域名含 `github`，都会直接中止

只更新 Mod 目录、不发管理器新版本时，省掉 `-ReleaseDir` 即可。

## 7. 验证

```powershell
.\tools\verify-mirror.ps1 `
    -BaseUrl https://mmm-mirror-1312774738.cos.ap-shanghai.myqcloud.com `
    -ExpectVersion 1.1.8
```

脚本会逐项检查并在最后汇总失败项：

- 地址是 https（`http` 会被客户端拒绝）
- 域名不含 `github`（见坑二）
- 两个清单可达，`latest.json` 的 version 与预期一致
- **逐个 Mod 拉下真实字节算 sha256，与目录声明比对**——这一步会直接暴露阶段 0 有没有做干净
- 每张预览图可达
- `setupUrl` 若指向本镜像，确认那个 exe 真的下得到；若指向别处（例如 GitHub）只提示一行，不算失败

不在 `tools/mirror-hot.txt` 里的 Mod 返回 404 时只记一行提示，不算失败——冷门内容本来就该回落到 GitHub Release。要求桶里必须有全量时加 `-RequireAll`。

再在管理器里做四步人工验证：

1. 设置 → 国内镜像地址填入根地址（**末尾不要斜杠**）→ Mod 浏览 → 刷新目录，日志应出现 `源=mirror`
2. 装一个 Mod，确认下载成功。这一步同时证明经镜像的 sha256 校验通过
3. 把镜像地址临时改成一个错误路径（如根地址后加 `/nope`），刷新目录，应自动回落且日志显示 `源=github`
4. 故意填一个 `http://` 地址，应被拒绝，日志出现「镜像地址必须使用 https」

验证完把地址改回正确值。

## 8. 接入发版流程

在 `docs/GitHub-Release更新说明.md` 的发版清单末尾已追加一步：GitHub Release 发布后运行 `sync-mirror.ps1`，再用 `verify-mirror.ps1 -ExpectVersion <新版本号>` 确认镜像的 `latest.json` 已经是新版本。

只更新 Mod 目录时，`git push` 之后同样要跑一次 `sync-mirror.ps1`（不带 `-ReleaseDir`），否则镜像上的目录会停留在旧版，而配了镜像的玩家优先读镜像——他们会看不到新 Mod。

新增或更新 Mod 的完整顺序是：

```powershell
# 1. 上传全量二进制到 GitHub Release，并把 originUrl 回填进 catalog.json
.\tools\publish-mods-release.ps1 -ModsRepo "D:\gongzuo\独立工作区\MechabellumMods"

# 2. 提交回填后的 catalog.json（CI 会校验 sha256 / size / originUrl）
cd "D:\gongzuo\独立工作区\MechabellumMods"; git add catalog.json; git commit -m "..."; git push

# 3. 同步热门子集到 COS
cd D:\gongzuo\钢铁指挥官mod管理器开发
.\tools\sync-mirror.ps1 -Bucket mmm-mirror-1312774738 -ModsRepo "D:\gongzuo\独立工作区\MechabellumMods"
```

第 1 步不能跳过：`originUrl` 缺失时，超过 100 MB 的 Mod 在 git 里根本不存在，raw 链接必然 404，而 COS 上又只有热门子集。

## 9. 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 刷新目录日志一直显示 `源=github` | 镜像地址填错、末尾多了斜杠、或用了 `http://` | 查日志有没有「镜像地址必须使用 https」；用 `verify-mirror.ps1` 复核 |
| 玩家能刷新目录但装不上任何 Mod | `catalog.json` 缺 `sha256` | 跑 `stamp_hashes.py` 补齐，重新 push 并同步镜像（坑一） |
| 装 Mod 报「下载文件校验失败」 | 镜像上的文件与目录声明的哈希对不上，通常是同步到一半 | 重跑 `sync-mirror.ps1`，再跑 `verify-mirror.ps1` |
| 所有请求 403 | 桶权限不是「公有读私有写」 | COS 控制台改权限 |
| 明明配了镜像却没有哈希保护 | 域名里含 `github` | 换桶名/域名（坑二） |
| 安装包传上镜像了，玩家点更新还是跳去 GitHub | 镜像那份 `latest.json` 的 `setupUrl` 没改写 | 用 `-IncludeSetup` 时补上 `-MirrorBaseUrl` 重跑 |
| 流量费突然飙升 | 被刷，或安装包镜像的下载量超预期 | 看第 5.3 的告警；必要时临时把桶改私有读止血 |

## 相关文件

- `tools/publish-mods-release.ps1` — 全量二进制传 GitHub Release，并回填 `originUrl`
- `tools/sync-mirror.ps1` — 增量上传热门子集，元数据最后传
- `tools/verify-mirror.ps1` — 只读验证，随时可对生产跑
- `tools/mirror-hot.txt` — 热门子集名单，决定哪些 Mod 进 COS
- `MechabellumMods/scripts/stamp_hashes.py` — 补 sha256 与 size，`--origin-base` 时补 originUrl
- `MechabellumMods/scripts/validate_catalog.py` — CI 校验 sha256 / size / originUrl
- `tests/MechabellumModManager.Tests/MirrorContractTests.cs` — 钉住本文档描述的客户端行为
- `tests/MechabellumModManager.Tests/LargeDownloadTests.cs` — 钉住大文件续传、空闲超时、gzip、候选回落
