# 给官方的建议（第二版）：一个不计分的沙盒房，社区自己做对战内容

接 2026-09-06 那封「沙盒空架子」建议，补上我们想清楚的两点：结果校验怎么处理、房里双方 Mod 怎么保证一致。还是玩家向、说人话版。

## 一句话

请官方给一个**不计分的沙盒房**，加四个很小的通道。规则内容、界面、预设、大厅、版本约定全部由社区负责，官方不用维护任何规则表。

硬前提不变：**正版、官服、走官方创建房间**，不搞私服，**不进匹配分、不进战力榜、不进正常匹配**。

## 为什么不是「拿一个现成模式改」

时空裂隙已经证明，你们能在同一套 1v1 / 2v2 骨架上按周期叠规则（补给、单位范围、科技等）。我们想要的是同一个思路，只是规则来源从「官方配置」换成「房间里带的数据」。

所以我们**不要**裂隙的入口，也不要它的积分和排行榜。裂隙是你们的内容，继续由你们安排；沙盒房是另外一个不计分的小开关。

## 请官方做的四件事

1. **沙盒标志**  
   创建房间时多一个「沙盒（不计分）」选项，可以是开房参数里一个开关，也可以是 GameMode 里一个新值。  
   沙盒房：不算匹配分、不进战力榜和裂隙积分、不出现在正常匹配里。

2. **沙盒房结果不判负**  
   现在服务器把自己演出来的战斗结果和客户端比较，不一致记 Data Error、本局判负。社区规则一改补给或禁单位，服务器那一遍就会和客户端不同，这条路在沙盒房里必然失败。  
   首选做法：沙盒房里**服务器不拿自己的结果比，改拿房内各客户端的结果互相比**。一致，这回合成立；不一致，这回合作废或本局记平，**不记 Data Error、不判负**。服务器不需要知道规则是什么，单边改结果仍然会被挡住。  
   退路做法：沙盒房不比较，直接采信结果，只记录不处罚。

3. **指纹锁房**  
   房间带一个有长度上限的字符串（社区用它写 Mod 组合和规则包的哈希）。加入的人必须提交相同的字符串才能进，不同就提示「Mod 方案不一致」。  
   服务器只比较两个字符串是否相等，不解释内容，也不需要知道有哪些 Mod。

4. **规则包只同步、不解释**  
   房间带一份有大小限制的数据（小 JSON 或键值包），开房时提交，服务器原样发给房内所有人（2v2 是四个人）。  
   禁哪个单位、补给怎么改，全部由双方装的同一套社区 Mod 按这份数据在本地执行。

四件事里，第 1、2 件是必须的；第 3、4 件没有的话，我们可以先在游戏外约定，只是体验差一些。

## 我们承担的部分

- 规则包格式、编辑器、预设，以及每份规则的说明
- Mod 方案锁定和指纹计算（Mod 管理器已经有方案、版本下限和冲突检查）
- 游戏外的大厅、约战、对局记录；需要的话社区自己做非官方排行
- 双方 Mod 版本约定，游戏更新后的适配
- 沙盒房里出的任何问题由社区解释，不要求官方客服处理

## 对官方的好处

- 不用写「禁单位 / 改补给」这些具体逻辑，也不用维护规则内容
- 每个版本都有缺陷引起的 Data Error；Mod 玩家进沙盒房后不再判负，这部分投诉会少一块
- 还是你们的房间系统和账号体系，不是私服，正式匹配和排位不受影响
- 随时可控：关掉沙盒开关、收紧规则包大小，都在你们手里

## 可以分阶段答应

- **现在（不需要官方）**：社区用现有的私人房间 + 邀请，只装纯界面类 Mod，先把约战的人聚起来。我们会把参与人数和反馈整理给你们。
- **第一步（官方）**：第 1、2 件，沙盒标志 + 结果不判负。
- **第二步（官方）**：第 3、4 件，指纹锁房 + 规则包同步。
- **以后（可选）**：如果你们愿意，规则包可以约定一个你们能选择性检查的格式，再往后才谈创意工坊之类。

有开发 / 策划看到的话麻烦看看可不可行，哪一步可以先做，谢谢！

（玩家 / 社区工具向，非官方）

- 裂隙有自己的积分：`RiftScore`、`riftScoreEloParams`、`LeaderboardScrollViewCell_Rift`。它不是不计分模式，这是信里明确不要裂隙入口的原因。
