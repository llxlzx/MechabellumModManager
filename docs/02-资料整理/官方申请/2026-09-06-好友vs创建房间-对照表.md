# 好友列表 vs 创建房间 — 一页对照

2026-10-13 更新：沙盒一列改为第二版申请函的四件事，新增「外部大厅 / 社区对战」一列。申请函见 `2026-10-13-sandbox-vs-mode-申请函-v2.md`。

| | **好友列表** | **创建房间（官服）** | **外部大厅 / 社区对战（不靠官方）** | **创建房间 · 沙盒空架子（需官方）** |
|--|--------------|---------------------|-------------------------------------|-------------------------------------|
| **目标** | 关注通讯录更好用 | 开房体验/协议内补齐 | 先把约战的人聚起来，证明有需求 | 补给、禁单位/科技等自由规则的对战 |
| **不靠官方就能做** | 搜索/筛选/排序/拉全列表；状态分组着色；行内接已有 API：观战/加入/私聊/取关/拉黑；可选 Discord 快捷 | 按模式尊重 UI：预设、校验、失败重试；异变窗搜索/分类；仅补「本模式协议已有、UI 未露」的旋钮 | 游戏外大厅、约战、对局记录、非官方排行；FriendOverlay 开私人房间并邀请；管理器锁定 Mod 方案和版本下限；只允许纯界面类（低风险）Mod | —（没有官方架子则不能合规联网自由改规则） |
| **做不到（不靠官方）** | 自建好友图、云备注/分组、站内完整私信、对局内比分/回合详情、强行互关 | 下拉没有的新模式；试验场级改补给/禁科技并当正式规则；修服务器故障；跨模式把所有旋钮塞一张表 | 改演算的规则（服务器比对会记 Data Error）；房间层面强制双方 Mod 一致；避开普通房的计分规则 | 私自改战斗且过战报校验（易 Data Error） |
| **要不要求官方** | **一般不需要**（调已有 `FriendProxy` 即可） | **协议内 QoL：不需要**；自由自定义：**需要** | **不需要** | **需要（四件）**：① 沙盒标志，不计分 ② 结果不判负，首选客户端互比、不一致作废 ③ 指纹锁房，只比字符串相等 ④ 规则包只同步不解释；①② 必须，③④ 可后补 |
| **官服战力/匹配分** | 基本不碰 | 普通房：不改结算逻辑则不碰 | 不碰（只用纯界面 Mod，私人房间） | 沙盒设计为**不计分**，也不进裂隙积分；普通房勿塞沙盒规则 |
| **法律/警告面** | 相对最低（纯 QoL） | 协议内 QoL 低；联网塞试验场工具 **高** | 低（不改演算） | 有官方沙盒通道则可控；无官方却改战报则高 |
| **推荐优先级** | P1 可独立开干 | P1 先做协议内 QoL | P1 现在就做，人数和反馈作为申请依据 | P0 用频道申请推进；未批前不要做联网改规则 |

**一句话：** 好友列表 = 现在就能 Mod；创建房间好看/好用 = 现在就能 Mod；社区约战（纯界面 Mod）= 现在就能做；创建房间「真正自由规则」= 必须等官方沙盒四件事，至少要沙盒标志和结果不判负，否则不要硬做。不要申请占用时空裂隙：它有自己的积分和排行榜。
